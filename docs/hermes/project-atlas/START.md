# Project Atlas — запуск для Hermes

**Цель:** один непрерывный проход по локальным проектам, GitHub, существующим промптам, памяти и LLM Wiki; затем отчёт и безопасное наведение порядка.

## Как работать
1. Прочитай только этот файл и текущий этап.
2. Продвигайся строго по порядку: 00 → 10 → 20 → 30 → 40 → 50. Не загружай все этапы и большие документы в контекст заранее.
3. Перед новым этапом прочитай локальную контрольную запись, затем только текущий файл этапа. Сохраняй короткий прогресс после каждого этапа.
4. Продолжай автоматически, не жди пользователя между этапами. Если одна задача заблокирована, зафиксируй точную причину и продолжай независимые задачи.
5. Не делай бесконечных повторов: одна целевая повторная проверка, затем BLOCKED и дальше.
6. Если сессия завершится или контекст начнёт заканчиваться, запиши checkpoint и остановись. При следующем запуске продолжай со следующего незавершённого этапа, не повторяя весь аудит.

**Файлы результата — локально, не в публичный GitHub:**
- прогресс: `$HOME/Документы/hermes-project-atlas-progress.md` (если каталога нет — файл в домашней папке);
- итоговый отчёт: `$HOME/Документы/hermes-project-atlas-report.md` (тот же fallback).
Не публикуй в этом публичном репозитории перечень личных файлов, локальные логи, MEMORY.md, USER.md, токены или частные данные.

Не сканируй всю домашнюю папку рекурсивно на содержимое. Найди только корни проектов, исключая модели, кэши, `node_modules`, виртуальные окружения, сборки и содержимое `.git`. Не меняй голосовую конфигурацию, не выводи секреты, не удаляй известные рабочие ISO. Никогда не пиши на физический USB или внутренний диск.

Начни с 00. Итог — проверенные факты, постоянные знания и одна следующая задача для каждого проекта, а не просто длинный пересказ.
