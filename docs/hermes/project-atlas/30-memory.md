# Этап 30 — память, GBrain, Wiki и skills

Не создавай конкурирующие хранилища. Сначала используй результаты этапа 00 и проверь фактические инструкции существующих компонентов.

- **GBrain:** структурированные факты о проектах, решениях, связях, блокерах и следующих шагах. Не инициализируй новую базу поверх найденной. Проверь реальную запись и recall через штатные команды; не сохраняй секреты.
- **LLM Wiki:** используй действующий skill `research/llm-wiki`, если он установлен. Поддерживай индекс, связанные Markdown-страницы, источники и проверку устаревших/противоречивых сведений. Не перечитывай всю Wiki при каждом запуске; индексируй только новые или изменённые источники.
- **Память Hermes:** держи `MEMORY.md`/`USER.md` короткими и только по делу. Ссылайся на карту знаний, не вставляй полный каталог проектов. Сохрани backup перед изменением и не перезаписывай другие настройки профиля.
- **Skills:** сначала используй `robot-factory-setup`, `screenpipe-hermes-memory` и другие подходящие навыки, если они реально доступны. Новый skill project-atlas создавать только если эквивалент не найден. Процедура должна загружаться по требованию и сохранять checkpoint.
- **Самосовершенствование:** используй `hermes-agent-self-evolution` roadmap как исследовательский материал. Не запускай платные API-оптимизации, GEPA/DSPy, массовую генерацию вариантов или автоматическую правку рабочих skills без отдельного согласования и тестов.
- **Screenpipe:** не включай постоянный захват экрана/аудио, облачную синхронизацию или автозапуск в рамках этого аудита. Проверка наличия не означает согласия включить запись.

Проверь каждый механизм отдельно. Успех означает, что данные удалось записать и найти, а не только что файл существует. Для новой сессии явно пометь cross-session-проверку как PASS только после реального теста в новой сессии. Не меняй рабочую голосовую конфигурацию.

Сохрани компактный архитектурный вывод: назначение каждого хранилища, фактический путь, статус проверки, как избежать дублирования и что обновлять после проектной задачи. Затем открой [40 — отчёт](40-report.md).
