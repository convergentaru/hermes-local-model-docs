# Этап 50 — безопасная реализация и синхронизация

Используй отчёт этапа 40 как план. Продолжай автоматически по проектам; если один заблокирован, зафиксируй причину и переходи к следующему. Не повторяй уже успешно завершённые проверки без изменения состояния.

## Память и документация
После резервной копии обнови подтверждённые карточки проектов, индекс Wiki/GBrain и короткую память/skills только там, где это действительно нужно. Не переписывай целиком существующие документы и не сохраняй догадки как факты. Не добавляй частные данные в публичные репозитории.

## Git-синхронизация
Перед каждым репозиторием проверь URL, ветку и `git status -sb`.
- Чистая рабочая директория и remote ahead: fetch и только fast-forward sync на правильной ветке.
- Локальные коммиты впереди: проверь историю, diff и файлы на секреты/большие бинарники перед push.
- Незакоммиченные изменения: сохрани их, не затирай, не используй `git add -A` без просмотра состава.
- Разошедшиеся ветки, сомнительный remote или конфликт: не делай reset/rebase/force-push; запиши план решения и продолжай с другими проектами.
- У локального Git-проекта без remote сначала перепроверь все доступные репозитории и историю. Если эквивалента нет, проект очевиден, история цела и проверка секретов/файлов пройдена, можно создать **приватный** репозиторий и синхронизировать исходную историю. Если назначение/владелец неоднозначны — не угадывай, отметь BLOCKED.
- Не публикуй токены, конфиги с секретами, личную память, логи с приватными данными, модели, ISO и прошивки. Большие бинарники храни отдельно; сохрани путь, размер и SHA-256.
- Не удаляй проекты/репозитории и не переписывай удалённую историю.

## Пределы самостоятельности
Не пиши на физический USB или внутренний диск, не меняй разделы, загрузчик, файловые системы, прошивки и ОС. Не удаляй известные рабочие ISO; любые новые образы — под новым версионным именем. Не устанавливай новые пакеты и не запускай платные процедуры самооптимизации без отдельного решения.

Перед каждой значимой правкой сохрани backup/diff. После изменения выполни доступные проверки, `git diff --check`, проверь состав файлов и подтверди итоговый commit/push по фактическому SHA. Не считай команду успешной без проверки результата.

## Режим длительной работы
- После каждого логического действия обновляй локальный checkpoint: DONE / PARTIAL / BLOCKED, что изменено, тест и следующий шаг.
- Максимум одна целевая повторная попытка при ошибке; затем запиши точный blocker и продолжай независимые задачи.
- Не создавай бесконечный цикл, cron или фоновый auto-pull. Работай до завершения безопасного плана или реального блокера; если сессия/контекст подходит к концу, сохрани checkpoint для продолжения.
- В конце оставь короткий итоговый отчёт: готово, не готово, пути/commit SHAs, проверки, риски и одна следующая задача по каждому важному проекту.
