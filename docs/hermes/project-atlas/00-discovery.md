# Этап 00 — обнаружить существующую систему

**Режим: чтение и диагностика.** Ничего не переустанавливай и не перенастраивай.

1. Прочитай текущий checkpoint, если он существует. Проверь, нет ли уже готового отчёта или результата этого этапа.
2. Инвентаризируй доступные инструменты: Hermes CLI/версия/профили, `hermes skills list`, Git/GitHub CLI и уже доступный GitHub API.
3. Проверь существующую память Hermes и поиск истории, GBrain (штатная диагностика вроде `gbrain doctor`, только если команда поддерживается), LLM Wiki и skill `research/llm-wiki`, Obsidian и проектные дашборды.
4. Найди прежние попытки промптов и runbook: локально — целевым поиском по именам и содержимому Markdown-файлов; на GitHub — по спискам файлов и известным репозиториям. Не читай все найденные документы подряд. Сначала составь список названий и путей, затем открывай только подходящие.
5. Учитывай, что часть правил уже существует:
   - `hermes-local-model-docs/docs/hermes/prompt-install-and-test-from-github.md`;
   - навыки `robot-factory-setup` и `screenpipe-hermes-memory`;
   - `pc-rescue-platform/docs/HERMES-GITHUB-SYNC-AND-CONTEXT.md`, `docs/PROJECT-CONTEXT-MAP.md` и bootstrap-промпты (для PC Rescue);
   - `hermes-agent-self-evolution/docs/HERMES-AGENT-MASTERCLASS-ROADMAP-RU.md);
   - инструкции GBrain из его репозитория.
6. Запиши, какой способ GitHub-доступа реально сработал и какие системы памяти/skills подтверждены тестом. Одна только настройка или наличие файла не доказывает работоспособность.

Не запускай установщики, не сбрасывай авторизацию, не запускай платную оптимизацию навыков и не меняй голосовой режим. При неоднозначности отметь BLOCKED и продолжай.

**Checkpoint:** коротко укажи обнаруженные инструменты, найденные существующие инструкции, уже выполненные проверки и следующую фазу. Затем открой [10 — аудит](10-audit.md).
