# Этап 10 — аудит локальных проектов и GitHub

Сначала используй инвентарь из этапа 00 и уже существующие инструкции. Не повторяй полный поиск, если результат ещё актуален.

## Локально
Найди корни Git-репозиториев и очевидных проектных папок в домашнем каталоге. Избегай моделей, кэшей, сборок, `node_modules`, virtualenv и глубокого чтения всех файлов. Включи известные ориентиры: `~/projects/acer-rescue-usb`, `~/robot-factory-os`, `~/local-llm-stack`, `~/projects/jarvis-linux-opencode`, GBrain и другие найденные проекты.

Для каждого проекта определи назначение, путь, ветку, remote, `git status -sb`, последние коммиты, незакоммиченные изменения и следующий незавершённый шаг.

## GitHub
Используй существующую авторизацию. Проверь правильный аккаунт и список доступных репозиториев. Сопоставляй по фактическим URL, Git-истории, веткам и содержимому, не только по названию. Не выдумывай адреса. 404 или отсутствие в поиске — «не подтверждено», а не автоматическое доказательство отсутствия приватного репозитория.

Для каждого проекта выбери состояние: синхронизирован; локальная версия впереди; удалённая версия впереди; ветки разошлись; локальный проект без remote; удалённый проект без локальной копии; состояние не установлено.

Найди дубликаты, общие компоненты, несогласованную документацию, незавершённые задачи, крупные бинарные файлы и возможные секреты. Значения секретов не выводи. Отдельно проверь, что информация из тематических репозиториев не ошибочно используется как remote для другого проекта.

## Ограничения
До завершения отчёта не меняй исходники и Git-состояние: без commit/push/pull/reset/rebase, смены веток/remotes, перемещения файлов и создания репозиториев. Записывать отчёт и checkpoint разрешено.

**Checkpoint:** таблица «локальный путь ↔ подтверждённый GitHub URL ↔ состояние ↔ риск ↔ следующий шаг». Продолжай к [20 — видео](20-video.md).
