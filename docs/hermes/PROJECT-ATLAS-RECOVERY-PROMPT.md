# Hermes: самовосстановление сессии и запуск Project Atlas

Используй этот промпт в **новом независимом окне/сессии Hermes**. Не продолжай и не возобновляй ту же заблокированную сессию через `--resume` или аналог, пока не выяснено, кто держит её turn lease.

## Задача
Самостоятельно восстановить рабочий процесс, использовать уже имеющийся GitHub-доступ и продолжить Project Atlas. Не проси пользователя выполнять диагностику вручную. Не делай вид, что выполнено то, что только планируется.

## 1. Восстанови исполнение, не плодя процессы
1. Сохрани/прочитай checkpoint, если он существует: `$HOME/Документы/hermes-project-atlas-progress.md`, иначе домашний `hermes-project-atlas-progress.md`.
2. Проверь процессы Hermes и их родительские процессы через доступный терминал. Определи, какой экземпляр держит нужную сессию и есть ли реальный прогресс. Не считай любой PID ошибкой.
3. Не запускай несколько исполнений с одним session ID. Не ставь новые сообщения в очередь одной занятой сессии.
4. Если holder живой и выполняет полезную работу, не убивай его: продолжай в текущей независимой сессии, пользуясь checkpoint. Если holder явно завис/осиротел и это подтверждено журналом/состоянием, используй только документированный механизм Hermes для безопасной остановки/перезапуска именно этого исполнения.
5. Не убивай рабочий голосовой CLI или несвязанные процессы, не удаляй вручную строки lease/state из базы данных, не очищай историю и не удаляй lock-файлы наугад. Не запускай `/new` в заблокированной сессии как замену диагностике.
6. Если безопасный способ освобождения не установлен, не импровизируй с удалением БД: зафиксируй точный blocker и продолжай доступную работу в независимой сессии.

## 2. Используй GitHub правильным способом
- Проверь `hermes skills list` и фактическую справку о поиске skills. Найди/загрузи установленный навык GitHub, если он доступен. Названия отличаются между установками — не угадывай и не заявляй, что навык загружен, не прочитав его.
- Прочитай `git remote -v` для существующего клона `convergentaru/hermes-local-model-docs`. Если клон уже есть, используй его. Не создавай вторую копию без необходимости.
- Репозиторий публичный; успешный `git clone git@github.com:convergentaru/hermes-local-model-docs.git` уже был подтверждён. Ошибка `web_extract` не доказывает, что репозиторий приватный.
- Для чтения используй уже работающий Git/терминал или точный raw URL, а не бесконечно повторяй неисправный extractor. START:
  `https://raw.githubusercontent.com/convergentaru/hermes-local-model-docs/main/docs/hermes/project-atlas/START.md`
- Не перенастраивай SSH/API, не генерируй новые ключи, не клонируй репозиторий повторно, если он уже существует, и не коммить результаты личного аудита в этот публичный репозиторий.

## 3. Продолжай пошагово
1. Прочитай только `docs/hermes/project-atlas/START.md) и текущий незавершённый этап.
2. Выполни этап 00, если он ещё не завершён; иначе продолжай с checkpoint.
3. Читай один этап за раз, сохраняй короткий checkpoint и не повторяй пройденные шаги.
4. После одной целевой повторной попытки по инструменту, который ошибся, запиши ошибку и переходи к доступному альтернативному способу. Не запускай бесконечный диагностический цикл.
5. Продолжай работу между этапами без ожидания отдельного одобрения на каждое безопасное, обратимое действие.

## Границы безопасности
Не выводи и не публикуй токены, ключи, cookies, MEMORY.md, USER.md, локальные логи с личными данными или секреты. Не меняй рабочий голосовой режим. Не удаляй и не перезаписывай проверенные ISO/прошивки, не пиши на физический USB/внутренний диск, не делай destructive Git-операций. Не запускай платные оптимизации и массовую самоперепись skills без отдельного согласования.

## Отчёт
Продолжай до завершения доступной безопасной работы. В checkpoint отмечай DONE / PARTIAL / BLOCKED, результат, источник доказательства и следующий шаг. Итоговый отчёт сохрани локально. Различай проверенные действия и планы.
