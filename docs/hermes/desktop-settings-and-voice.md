# Hermes Desktop: настройки, auxiliary-модели и голос

Дата заметок: 2026-10-10.

## Панель Model и auxiliary-задачи

- **Main Model / Context Length:** основная модель и лимит контекста. Значение должно поддерживаться моделью и работающим сервером.
- **Auxiliary Models:** отдельные фоновые задачи, например compression, web extraction, vision, title generation, skills hub и другие. Это дополнительные вызовы модели, а не основной ответ.
- Не считать `provider: auto` гарантией нужного локального маршрута: фактический выбор зависит от настроенных провайдеров и текущей реализации.
- В нашей конфигурации Hermes сообщил минимум 64,000 токенов для compression-пути. Ошибка основной модели также указывала, что серверное окно 4096 меньше необходимого минимума.

## История проблемы контекста

Qwen3.6-35B на порту `8999` запускалась с `-c 4096`; экспериментировали с `-c 8192`. Попытка `-c 65536` зависила компьютер, после чего исходный скрипт был восстановлен. Не повторять это на нынешнем железе.

Была выполнена команда:

~~~bash
hermes config set compression.enabled false
~~~

Она записала `compression.enabled = false` в конфигурацию CLI, но сама по себе не сняла требование к контексту основной модели. Поэтому не считать её окончательным исправлением. Текущий UI-путь Unsloth подключён отдельно; повторно проверить актуальное поведение на новой модели.

## Голосовые настройки, которые пользователь увидел в UI

- **Voice Chat Mode:** варианты `Chained` и `GPT Live` / связанные duplex-варианты.
- **Speech-to-Text:** включён; включена проверка/подтверждение расшифровки.
- Локальный STT-переключатель показывает модели Whisper: `base`, `small`, `medium`, `large-v3`.
- Язык транскрипции изначально не задан.
- Есть отдельные настройки **Text-to-Speech**, провайдера и голоса. Точные названия всех вариантов не записаны по скриншоту — не угадывать их при настройке.

Режим `Chained` описывает цепочку этапов STT → языковая модель → TTS. Он сам по себе не гарантирует, что каждый этап локальный; нужно отдельно проверить выбранный backend каждого компонента.

## План голосовой настройки

1. Сохранить проверенный текстовый маршрут Hermes → Unsloth.
2. Для самого быстрого smoke test оставить `Chained`, включить STT и выбрать язык Russian, если поле доступно; проверить штатный Whisper в Hermes.
3. Затем, если требуется качество Qwen3-ASR, отдельно проверить API Unsloth для транскрипции и совместимость с Hermes. Сам факт, что Qwen3-ASR распознаёт речь в Studio, не означает, что Hermes уже обращается к этой модели.
4. Проверить TTS отдельным коротким ответом. ASR-модель распознаёт речь, но не озвучивает ответ.
5. Только после текстового и голосового теста перенастраивать auxiliary-модели.

## Auxiliary-маршрутизация

Статья [про фоновый расход](https://habr.com/ru/articles/1042860/) объясняет идею явного распределения моделей по задачам. Автор использует облачные модели и свой набор провайдеров; его YAML нельзя копировать напрямую в локальную конфигурацию.

У нас: сначала стабильная главная модель, затем проверка контекста каждой auxiliary-задачи. Не загружать несколько тяжёлых GGUF на одну GPU с 12 GB VRAM без повторного замера. После изменений открывать новую сессию или перезапускать Hermes согласно текущей версии.

## Безопасность

- Не публиковать `~/.hermes/config.yaml` целиком.
- Перед ручными изменениями делать резервную копию.
- Не копировать сторонние ключи/облачные настройки.
- Не включать auto-approve всех команд ради быстроты.
