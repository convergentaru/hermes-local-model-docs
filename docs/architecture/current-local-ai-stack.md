# Архитектура локального AI-стека

Дата фиксации: 2026-10-10.

## Цель

Использовать одну общую библиотеку моделей и GUI для их выбора/запуска, а сверху подключать разные агенты. Hermes Desktop остаётся главным помощником, включая голосовой сценарий. Кодовые агенты используются для разработки, но не заменяют Hermes.

## Компьютер

- Ubuntu-хост: `ubuntu26`.
- GPU: NVIDIA GeForce RTX 3060, 12 GiB VRAM.
- Системная RAM: около 11 GiB.
- Swap: 4 GiB.
- Модели: `/home/oleg/models`.
- Собственный runner: `/home/oleg/llama.cpp/build-cublas/bin/llama-server`.
- Сборка содержит CUDA-библиотеки; исполняемый файл существует и имеет права запуска.

## Текущая рекомендуемая схема

~~~text
Unsloth Desktop
  ├─ Model Hub / общая библиотека ~/models
  ├─ GGUF inference engine: CUDA
  ├─ Custom llama.cpp folder:
  │    /home/oleg/llama.cpp/build-cublas/bin
  └─ API сервера Unsloth (управляемый порт и авторизация)
       ├─ Hermes Desktop: unsloth start hermes --app
       └─ позже: Little-coder / другие агенты через совместимый API
~~~

Каталог модели и каталог движка — разные настройки. Модели находятся в `~/models`; Custom llama.cpp folder указывает на каталог с исполняемыми файлами и библиотеками.

## Дополнительная инфраструктура

- Старый маршрут: Hermes → LiteLLM (`127.0.0.1:4000`) → llama-swap (`127.0.0.1:8080`) → llama.cpp. Не менять его ради Unsloth без отдельного решения.
- Экспериментальный порт Qwen3.6-35B: `8999`; сервер остановлен по последней проверке.
- Unsloth Studio API на порту `8888` отвечает `Not authenticated` на запрос без авторизации. Это ожидаемо для защищённого API.
- Во время последней проверки сервер Qwen3.5-4B работал на динамическом порту `36679`. Не считать этот порт постоянным.

## Подключение Hermes

В установленной версии команда `unsloth start hermes --app` добавляет провайдера Unsloth в конфигурацию desktop-приложения и сохраняет резервную копию перед изменением. После смены модели в Unsloth команду нужно выполнить повторно, согласно выводу справки установленной версии.

Команда была выполнена в ходе сеанса; после неё визуальный Hermes вернул контрольную строку. Это подтверждает базовый текстовый маршрут, но не доказывает готовность голосового канала.

## Контекст и память

1. Размер контекста в API не гарантирует, что любая длинная сессия или несколько параллельных запросов будут безопасно помещаться в память.
2. Не запускать Qwen3.6-35B с 64K на текущем компьютере: предыдущая попытка вызвала зависание.
3. Qwen3.6-35B при контексте 8K оказалась тесной для сложного запроса Aider с несколькими файлами и длинным ответом.
4. Unsloth запустил Qwen3.5-4B с `-c 238592`, `--parallel 4` и `--fit off`. API сообщил `n_ctx=238592` и `n_ctx_train=262144`. Это факт командной строки/метаданных, а не доказательство устойчивости всех слотов на максимальном контексте.
5. В том же снимке использовалось 11,425 из 12,288 MiB VRAM, доступная RAM — около 5.0 GiB. Не запускайте вторую тяжёлую модель на GPU без повторной проверки ресурсов.
6. Не устанавливать контекст Hermes больше реально доступного контекста сервера.

## Секреты

Не коммитить `~/.hermes/config.yaml` целиком, `.env`, API keys, пароли, токены, локальные key-файлы Unsloth или заголовки авторизации. Документировать безопасные пути и названия параметров, но не значения секретов.
