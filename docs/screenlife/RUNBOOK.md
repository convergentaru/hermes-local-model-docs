# Runbook: повторный запуск Screenlife-сессии

Цель: поднять один Unsloth llama-server с Qwen3.5-9B, подключить Claude Code и использовать тот же Unsloth endpoint из работающего Hermes Gateway.

## Перед запуском

- Ubuntu 26.
- Unsloth CLI установлен.
- Модель доступна по пути `/home/oleg/.hermes/models/Qwen3.5-9B-Q4_K_M.gguf`.
- Hermes настроен на Custom endpoint `http://127.0.0.1:8888/v1`.
- В Hermes сохранено `local_runtime.enabled=false`.

Первичная настройка Hermes выполняется один раз; подробности — в [COMMANDS.md](COMMANDS.md).

## Терминал 1 — Unsloth API и модель

Из корня репозитория:

```bash
./docs/screenlife/scripts/start-unsloth.sh
```

Скрипт проверяет модель, не запускает дубликат, если API уже отвечает, и прекращает запуск, если обнаружен другой `llama-server`. Затем запускает Unsloth API на `127.0.0.1:8888`, context 160K, один слот.

Оставить терминал работающим.

## Терминал 2 — Claude Code

```bash
./docs/screenlife/scripts/start-claude-code.sh /path/to/working-project
```

Скрипт проверяет API и количество движков, затем выполняет `unsloth start claude --no-serve`. Не используйте Chat в Studio для отдельной загрузки модели.

## Hermes Gateway

Gateway уже настроен на Custom endpoint и работает через Unsloth. При обычном старте компьютера использовать существующую пользовательскую службу Hermes Gateway.

Если Gateway действительно остановлен и не запущен, после старта Unsloth выполнить:

```bash
hermes gateway restart --detach
```

Команда проверена 31.10.2026. Она перезапускает Gateway; не выполнять без необходимости во время активных ходов.

Не включать Hermes local runtime обратно: это снова поднимет отдельный Hermes llama-server.

## Проверка

```bash
./docs/screenlife/scripts/check-session.sh
```

Ожидается один `llama-server`, принадлежащий Unsloth; Unsloth API :8888 — HTTP 200; внутренний порт модели обнаружен из фактической командной строки; старый порт Hermes :18434 не слушает.

## Сценарий съёмочного теста

1. Включить запись рабочего стола и отдельных агентских окон, если доступны независимые источники записи.
2. Записать дату, время, версии агентов и модель.
3. Подать один и тот же prompt обоим агентам.
4. Дать завершить задачу одному агенту, затем второму — при одном слоте.
5. Сохранить запрос, ответы, видимые tool calls, ошибки и длительность.
6. Не редактировать оригинальные transcript-файлы; монтажные заметки хранить отдельно.

Скрипты подготовлены по использованным командам, но не запускались повторно после публикации. Первое применение после клонирования — отдельная проверка на целевой машине.
