# Unsloth Desktop: библиотека моделей, CUDA и собственный llama.cpp

Дата фиксации: 2026-10-10.

## Цель

Использовать GUI для выбора, запуска и остановки моделей, не переписывая длинные команды запуска вручную.

## Общая библиотека моделей

Все GGUF-модели находятся под:

~~~text
/home/oleg/models
~~~

Если в установленной версии есть раздел **Custom Folders**, добавлять этот путь в Model Hub, не перемещая и не копируя веса. Важное различие: папка моделей и папка движка — два разных поля.

## GGUF Inference Engine

В UI пользователь видел варианты Automatic, CUDA, CPU и Vulkan (конкретный набор зависит от версии). Для NVIDIA RTX 3060 выбран **CUDA**.

## Подключённая сборка llama.cpp

В разделе **Custom Llama CPP Folder** → **Change** был указан каталог:

~~~text
/home/oleg/llama.cpp/build-cublas/bin
~~~

Unsloth Desktop принял путь. Проверка терминалом подтвердила:
- бинарник `llama-server` есть и исполняемый;
- библиотека `libggml-cuda.so.0.25.3` присутствует;
- `libllama-server-impl.so` присутствует.

Фактический процесс после загрузки модели запускал именно `/home/oleg/llama.cpp/build-cublas/bin/llama-server`. Короткий тест ответил `UNSLOTH_CUDA_TEST_OK`, UI сообщил `68.4 tok/s`. Это smoke test, а не полный сравнительный бенчмарк против bundled runner.

Если пользовательская сборка перестанет запускаться после обновления, сначала переключить движок на Automatic/Bundled в UI. Не удалять собственную сборку.

## Qwen3.5-4B: фактически наблюдавшийся процесс

Модель:

~~~text
/home/oleg/models/qwen35-4b/Qwen3.5-4B-Q4_K_M.gguf
~~~

Наблюдавшаяся командная строка включала:
- alias `qwen35-4b`;
- порт `36679` (динамический, может измениться);
- `-c 238592`;
- `--parallel 4`;
- `--kv-unified`;
- `--fit off`;
- `-ngl -1`;
- Flash Attention, Jinja и reasoning.

API `/v1/models` сообщил `n_ctx=238592` и `n_ctx_train=262144`. Число `238592` пришло из командной строки работающего сервера, не просто из надписи в UI.

Память в том же снимке:
- RAM: 11 GiB всего, около 5.0 GiB доступно;
- swap: 4.0 GiB всего, около 1.7 GiB использовалось;
- VRAM: 11,425 MiB из 12,288 MiB.

Запуск успешен, но свободной VRAM мало. Не загружать вторую модель на GPU одновременно без нового замера. Максимальный контекст в метаданных не равен гарантии устойчивой работы четырёх длинных параллельных запросов.

## API и авторизация

Запрос к `http://127.0.0.1:8888/v1/models` без авторизации вернул `Not authenticated`. Это подтверждает защиту API, а не неисправность. Ключи лежат в локальном auth-каталоге Unsloth; их значения не сохранять в репозитории и не печатать в терминал.

## Подключение к визуальному Hermes

После загрузки нужной модели запускается:

~~~bash
unsloth start hermes --app
~~~

Справка текущей версии говорит, что команда добавляет провайдера Unsloth и его API key в настройки desktop-приложения, предварительно создавая резервную копию и не заменяя основную модель по умолчанию. После загрузки другой модели в Unsloth команду нужно повторить, чтобы обновить привязку.

Команда была выполнена; затем визуальный Hermes ответил контрольной строкой. Это доказывает текстовый маршрут Hermes ↔ Unsloth, но не аудиоинтеграцию.
