# Screenpipe + Hermes: локальная экранная память и поиск

**Цель:** Screenpipe локально сохраняет экранный контекст и (только если пользователь отдельно включает) аудиотранскрипции. Hermes получает доступ к поиску истории через MCP. Это даёт связку «смотрю/работаю → Screenpipe индексирует → Hermes находит прошлый контекст → выполняет задачу».

## Проверенная архитектура

- Screenpipe desktop app доступен для Linux x86_64 как AppImage; точку загрузки открывать с официального сайта: https://screenpi.pe
- Screenpipe локально предоставляет REST API на `http://127.0.0.1:3030`.
- Официальный пакет `screenpipe-mcp` предоставляет MCP-инструменты поиска экранного текста (OCR/accessibility), аудиотранскрипций, просмотра кадров и сводок активности.
- Hermes поддерживает локальные stdio MCP-серверы в `~/.hermes/config.yaml` в секции `mcp_servers`.
- Требования Screenpipe MCP: Screenpipe должен быть запущен на этом компьютере, Node.js >= 18 и доступный `npx`.

Источники:
- https://github.com/screenpipe/screenpipe
- https://docs.screenpi.pe/mcp-server
- https://github.com/screenpipe/screenpipe/blob/main/packages/screenpipe-mcp/README.md
- https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp

## Важная политика приватности и ресурсов

Экранные записи и распознанный текст могут содержать личные сообщения, пароли, финансовые страницы и другие секреты.

1. Не включать непрерывную аудиозапись/микрофон без отдельного согласия пользователя. Для первого запуска используем экранную память, аудио выключено.
2. По возможности настроить исключения приватных приложений и окон, ограничить хранение и проверить размер данных.
3. Отключить cloud sync и cloud AI, оставить локальную обработку. Screenpipe сообщает, что аналитика включена по умолчанию; если пользователь хочет максимально local-first режим, выключить её в Settings → Privacy → Analytics.
4. Не печатать токены API и не добавлять ключи в GitHub.
5. Не выставлять Screenpipe API или MCP на LAN/публичный интерфейс. Использовать только loopback.
6. Не создавать постоянный сервис записи автоматически. Сначала запустить приложение вручную, настроить Privacy/Retention, проверить захват, а затем спросить согласие на запуск при входе.
7. Screenpipe оценивает потребление захвата примерно в 0.5–3 GB RAM и 5–20% CPU в зависимости от настроек; на машине примерно с 11 GiB RAM начинаем с минимального набора потоков и проверяем ресурсы. Не запускаем отдельную тяжёлую локальную AI-модель внутри Screenpipe параллельно с Unsloth.

## Шаг A — инвентаризация (только чтение)

В терминале через Hermes Terminal tool проверь:
- `command -v screenpipe`
- `command -v node` и `node --version`
- `command -v npx`
- `ss -ltnp | grep -E ':(3030|3031)\\b' || true`
- `curl -fsS --max-time 3 http://127.0.0.1:3030/health` (если API отвечает)
- `free -h`
- `pgrep -af 'screenpipe|screenpipe-mcp' || true`

Не делай вывод, что запись исправна лишь по PID или открытому порту. Если Screenpipe CLI доступен, сначала ознакомься с командой `screenpipe status` / `screenpipe doctor`. Не запускай команды, которые устанавливают системный сервис или начинают запись, пока не выяснишь текущее состояние.

## Шаг B — установка Screenpipe, если его нет

1. Открой официальный сайт https://screenpi.pe и выбери Linux AppImage для x86_64. Не скачивай бинарник с зеркал или случайных форумов.
2. Запусти Desktop app вручную. Дай необходимые разрешения для захвата экрана в Ubuntu, если ОС их запросит.
3. В настройках Privacy/Capture выключи захват звука на первом этапе, оставь облачную синхронизацию и cloud AI выключенными, проверь исключения приватных окон и доступные настройки Retention.
4. Не включай автозапуск сервиса записи, пока пользователь не подтвердит, что хочет постоянную запись.
5. Проверь, что появляются свежие экранные записи и локальный API работает.

Если AppImage/GUI не работает, не переходи к самостоятельной сборке из исходников без отдельного решения: сначала собери точную ошибку и проверь официальные Linux инструкции.

## Шаг C — подключение MCP к Hermes

**Перед редактированием config.yaml сделай копию с временной меткой и проверь существующую секцию mcp_servers. Не заменяй весь файл и не перезаписывай другие MCP-серверы.**

Hermes поддерживает stdio MCP. Минимальный блок для добавления (merge, не полная замена секции):

```yaml
mcp_servers:
  screenpipe:
    command: "npx"
    args: ["-y", "screenpipe-mcp@latest"]
```

Условия:
- Это иллюстративный фрагмент только для случая, если такого сервера ещё нет.
- Если в текущем конфиге `mcp_servers` уже есть, добавь только ключ `screenpipe`, сохрани все остальные записи и параметры.
- Если `npx` не найден, остановись и сообщи версию Node.js; не устанавливай Node и пакеты без согласия.
- Официальный MCP-клиент пытается найти local API key автоматически, если переменная `SCREENPIPE_LOCAL_API_KEY` не передана. Если сервер вернёт 401/403, используй официальный `screenpipe auth token` для проверки и храни токен локально, не в репозитории. Не вставляй секрет в отчёт.
- Не запускай `npx screenpipe setup` вслепую: этот мастер может настраивать несколько обнаруженных агентных сред. Сначала проверяй текущий конфиг и вноси узкое изменение только в Hermes.
- Перезапусти Hermes Desktop полностью или открой новую сессию, чтобы MCP-инструменты были обнаружены.

## Шаг D — проверка настоящего тандема

1. В обычном текстовом редакторе создай временную тестовую строку без секретов: `SCREENPIPE_HERMES_TEST_2026`.
2. Дождись, пока Screenpipe захватит экран и проиндексирует текст.
3. В Hermes попроси найти именно эту строку в экранной истории через Screenpipe MCP. Пусть он сообщает инструмент и временную метку результата.
4. Проверь HTTP/API и MCP отдельно. Наличие MCP-сервера ещё не доказывает, что Screenpipe записывает свежие данные.
5. Удали тестовый документ, если он больше не нужен; запись останется в истории, пока не истечёт retention или пользователь её не удалит.
6. В отчёте укажи PASS/FAIL отдельно для: screen capture, local indexing/search, Hermes MCP discovery, поиск тестовой строки. Не объявляй интеграцию завершённой только по успешному старту процесса.

## Какую задачу даст Олег

После успешной проверки Hermes сможет получать задачи вида:
- «Найди, на чём я остановился вчера в Robot Factory OS».
- «Найди окно, в котором я видел ошибку установки, и вытащи точный текст».
- «Собери краткий дневник работы за сегодня по проектам, которые я открывал».
- «Найди обсуждение про настройку голосового ввода и продолжи с последнего проверенного шага».

Поиск должен выдавать временные метки и источники. Не выполнять действия на найденном содержимом автоматически, если задача требует рискованных изменений.
