# Кодовые агенты: Aider и Little-coder

Последнее обновление: 2026-10-10.

## Цель

Нужен локальный агент для небольших сайтов, WordPress-тем, плагинов и автоматизаций — без платного API и переполнения контекста.

## Aider: установлен и испытан

- Aider: `0.86.2`.
- uv: `0.12.1`.
- Установка: `uv tool install --python 3.12 aider-chat`.
- Тестовый проект: `~/aider-qwen-test`; в нём есть тема `~/aider-qwen-test/theme-name` и Git-репозиторий.

### Историческое подключение к Qwen3.6-35B

Когда отдельный сервер работал на порту 8999, использовалась команда:

~~~bash
cd ~/aider-qwen-test
OPENAI_API_BASE=http://127.0.0.1:8999/v1 \
OPENAI_API_KEY=local-no-key \
aider --model openai/qwen3.6-35b-experiment \
  --map-tokens 0 \
  --no-auto-commits \
  --no-show-model-warnings \
  --no-show-release-notes
~~~

Это относится только к отдельному серверу на порту 8999. Он остановлен; текущий Unsloth использует управляемый порт и локальную авторизацию. Не запускать указанную команду, пока тот сервер не поднят.

### Команды Aider

- `/ask` — обсуждение и план.
- `/code` — режим изменения кода.
- `/tokens` — оценка контекста.
- `/drop` — убрать файлы из контекста.
- `/clear` — очистить историю.
- `/diff` — показать изменения.
- `/exit` — выйти.

`--map-tokens 0` отключает repo map. Лучше держать в контексте только нужные один-два файла.

## Результаты тестов

1. Короткая задача: Aider создал `hello.py`; отчёт — 637 токенов отправлено, 212 получено.
2. `/run python hello.py` не сработал: в Ubuntu доступна команда `python3`, а команда `python` не найдена. Проверять через `/run python3 hello.py`.
3. Запрос WordPress с окном 4096 завершился ошибкой: `request (4191 tokens) exceeds the available context size (4096)`.
4. При 8192 токенах длинный запрос и ответ заняли примерно 7,594 + 2,144 = 9,738 токенов, что превышает 8,192; Qwen также вывела длинное рассуждение.
5. Итог: Aider работает для небольших отдельных изменений, но нужно ограничивать количество файлов и объём ответа. Большой контекст клиента не может увеличить фактическое окно сервера.

## Little-coder

Пользователь подтвердил, что Little-coder уже установлен. В последнем сеансе он **не проходил отдельный smoke test**, поэтому результат пока неизвестен.

Рациональный тест после стабилизации:
1. подключить его к локальному API текущего агента или к отдельно управляемой маленькой модели;
2. назначить рабочую папку тестовой темы;
3. дать одно задание на изменение одного файла;
4. проверить diff, запустить тест и убедиться, что файл действительно изменён;
5. прекратить эксперимент, если агент не может работать в рамках доступного контекста/памяти.

Не тестировать его на Qwen3.6-35B с 64K на нынешнем компьютере.

## Рабочая стратегия

1. Начинать с одного файла; второй добавлять только при необходимости.
2. Просить короткий ответ и конкретный diff.
3. Проверять файлы и запускать тесты, а не принимать текстовый отчёт за подтверждение успеха.
4. Держать Git под контролем и смотреть изменения.
5. Не публиковать API-ключи и конфиги, содержащие секреты.
