# Qwen3.6-35B-A3B на Ubuntu с RTX 3060 12 GB: установка и запуск через llama.cpp

Практическая инструкция для запуска **только одной модели — Qwen3.6-35B-A3B** на Ubuntu. Она адаптирована под компьютер с NVIDIA RTX 3060 12 GB, примерно 11 GiB системной RAM и 4 GiB swap. В качестве основы использованы подходы из статьи на Хабре про запуск Qwen3.6-35B-A3B на видеокарте с 12 GB VRAM и рекомендации по запуску MoE-моделей в llama.cpp.

- Статья на Хабре: https://habr.com/ru/articles/1026482/
- Объяснение квантов и запуска Qwen3.6-35B-A3B через llama.cpp: https://habr.com/ru/articles/1025132/
- Проект llama.cpp: https://github.com/ggml-org/llama.cpp
- Репозиторий моделей Qwen3.6-35B-A3B GGUF: https://huggingface.co/unsloth/Qwen3.6-35B-A3B-GGUF

> Важно: в исходной статье на Хабре использовалась машина с 32 GB RAM и квант Q4_K_M примерно на 22 GB. У этого компьютера около 11 GiB RAM, поэтому нельзя слепо копировать настройки Q4_K_M. Здесь используется уже выбранный файл `Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf` и небольшой контекст для первого запуска. Более агрессивная квантизация снижает требования к памяти, но может снижать качество.

## 1. Проверить оборудование и драйвер NVIDIA

Откройте терминал Ubuntu и выполните:

```bash
nvidia-smi
free -h
lsb_release -a
```

Убедитесь, что система видит RTX 3060 и драйвер NVIDIA работает. На этой конфигурации видеопамять — 12 GB, системная память — около 11 GiB, swap — 4 GiB.

Если `nvidia-smi` не работает, сначала установите и проверьте драйвер NVIDIA для своей версии Ubuntu. Не продолжайте сборку CUDA, пока GPU не видна системе.

## 2. Установить зависимости для сборки llama.cpp

```bash
sudo apt update
sudo apt install -y git cmake build-essential pkg-config libcurl4-openssl-dev
```

Для сборки с CUDA нужен установленный CUDA Toolkit, включая `nvcc`. Проверьте:

```bash
nvcc --version
```

Если `nvcc` не найден, установите CUDA Toolkit, совместимый с драйвером и инструкциями NVIDIA для вашей версии Ubuntu. Не путайте наличие драйвера NVIDIA с наличием CUDA Toolkit: это разные компоненты.

## 3. Скачать и собрать llama.cpp с поддержкой CUDA

Если репозиторий ещё не склонирован:

```bash
git clone https://github.com/ggml-org/llama.cpp.git ~/llama.cpp
```

Перейдите в каталог и соберите сервер для архитектуры RTX 3060 (compute capability 8.6):

```bash
cd ~/llama.cpp
cmake -B build-cuda -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=86 -DCMAKE_BUILD_TYPE=Release
cmake --build build-cuda --config Release --target llama-server -j2
```

Проверка бинарника:

```bash
~/llama.cpp/build-cuda/bin/llama-server --version
```

На компьютере, где `llama.cpp` уже собран с CUDA, повторно собирать его не нужно. Используйте имеющийся бинарник, например `~/llama.cpp/build-cublas/bin/llama-server`, если он успешно запускается и поддерживает нужные параметры.

## 4. Создать каталог модели

```bash
mkdir -p ~/models
```

В этом руководстве используется квантованный GGUF-файл:

```text
Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf
```

Если файл уже есть, проверьте его расположение и размер:

```bash
ls -lh ~/models/Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf
```

В текущей рабочей конфигурации файл уже находится по пути:

```text
/home/oleg/models/Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf
```

Если вы устанавливаете модель заново, откройте страницу GGUF на Hugging Face, найдите именно файл `Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf` и скачайте его в `~/models`. Перед загрузкой проверьте точное имя файла и доступность этого кванта в репозитории. Не переименовывайте файл в случайное имя, если затем будете копировать команды из этой инструкции.

Для загрузки через CLI Hugging Face можно использовать `hf` из пакета `huggingface_hub`:

```bash
sudo apt install -y python3-venv
python3 -m venv ~/venvs/hf-download
source ~/venvs/hf-download/bin/activate
python -m pip install --upgrade pip
python -m pip install -U huggingface_hub
hf --help
```

Затем выполните загрузку, подставив актуальный ID репозитория и точное имя файла, которые показаны на странице модели:

```bash
hf download unsloth/Qwen3.6-35B-A3B-GGUF \
  --include 'Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf' \
  --local-dir ~/models
```

Если файл с таким именем отсутствует в репозитории, не запускайте команду снова вслепую: проверьте список файлов на Hugging Face и выберите реально существующий GGUF. По завершении:

```bash
ls -lh ~/models/Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf
```

## 5. Первый запуск модели

Начните с короткого контекста, чтобы проверить, что модель загружается. Пример команды для `llama.cpp`:

```bash
~/llama.cpp/build-cuda/bin/llama-server \
  --model ~/models/Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf \
  --ctx-size 4096 \
  --n-gpu-layers 999 \
  --flash-attn on \
  --jinja \
  --host 127.0.0.1 \
  --port 8999 \
  --alias qwen3.6-35b-experiment
```

Если ваш рабочий бинарник находится в `build-cublas`, замените путь к `llama-server` на:

```text
~/llama.cpp/build-cublas/bin/llama-server
```

Пояснения:

- `--ctx-size 4096` — начальный контекст 4096 токенов; он выбран для проверки запуска, а не как универсально оптимальное значение.
- `--n-gpu-layers 999` просит выгрузить на GPU максимально возможное число слоёв. Это не гарантирует, что все веса и кэш поместятся в VRAM.
- `--flash-attn on` включает Flash Attention, если поддерживается собранной версией и моделью.
- `--jinja` использует chat template модели, если он корректно содержится в GGUF.
- `--host 127.0.0.1` оставляет API доступным только локально.
- `--port 8999` использует отдельный порт, не конфликтующий с существующими сервисами на 4000 и 8080.

На системе с 11 GiB RAM запас небольшой. Если процесс завершается из-за нехватки памяти, сначала проверьте сообщения сервера, `free -h` и `nvidia-smi`. Не увеличивайте контекст до подтверждения стабильного запуска. Возможность переноса MoE-весов на CPU зависит от версии llama.cpp и доступных параметров; сначала проверьте `llama-server --help` и используйте только флаги, поддерживаемые вашей сборкой.

## 6. Проверить ответ модели

Оставьте сервер работающим и откройте второй терминал:

```bash
curl -sS http://127.0.0.1:8999/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3.6-35b-experiment",
    "messages": [
      {"role": "user", "content": "Ответь ровно: QWEN35_OK"}
    ],
    "temperature": 0
  }'
```

Успех: в JSON-ответе есть текст, сгенерированный моделью. Если запрос не проходит, проверьте:

1. Не завершился ли процесс `llama-server`.
2. Правильно ли указан путь к GGUF.
3. Не занят ли порт `8999`.
4. Что написано в терминале сервера при загрузке модели.
5. Достаточно ли RAM и VRAM.

Проверить порт можно командой:

```bash
ss -ltnp | grep ':8999'
```

## 7. Остановить и запускать повторно

Остановить сервер можно сочетанием `Ctrl+C` в терминале, где он запущен.

Для удобного повторного запуска сохраните команду в скрипт:

```bash
mkdir -p ~/experiments/qwen3.6-35b
nano ~/experiments/qwen3.6-35b/run.sh
```

Вставьте, при необходимости исправив путь к `llama-server` и GGUF:

```bash
#!/usr/bin/env bash
set -euo pipefail

LLAMA_SERVER="$HOME/llama.cpp/build-cuda/bin/llama-server"
MODEL="$HOME/models/Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf"

exec "$LLAMA_SERVER" \
  --model "$MODEL" \
  --ctx-size 4096 \
  --n-gpu-layers 999 \
  --flash-attn on \
  --jinja \
  --host 127.0.0.1 \
  --port 8999 \
  --alias qwen3.6-35b-experiment
```

Сохраните файл, затем выполните:

```bash
chmod +x ~/experiments/qwen3.6-35b/run.sh
~/experiments/qwen3.6-35b/run.sh
```

Если у вас уже есть рабочий экспериментальный скрипт в `~/local-llm-stack/experiments/qwen3.6-35b/run.sh`, не создавайте дубликат без необходимости: сохраните существующий скрипт и используйте его.

## 8. Что означает 35B-A3B

`35B` — общее количество параметров модели. `A3B` означает, что в MoE-архитектуре на каждом токене активируется примерно 3 миллиарда параметров, а не все 35 миллиардов. Это уменьшает вычисления на токен, но **не означает**, что весь файл весов занимает память как обычная 3B-модель. Поэтому важны квантование, системная RAM, VRAM и размер контекста.

## 9. Критерии готовности

Установка считается завершённой, когда:

- `llama-server` успешно стартует с выбранным GGUF;
- сервер слушает `127.0.0.1:8999`;
- тестовый `curl` возвращает ответ модели;
- повторный запуск через скрипт работает;
- во время генерации система не уходит в постоянный swap и процесс не завершается по OOM.

Это инструкция именно для установки и запуска **Qwen3.6-35B-A3B**. Настройка Hermes, LiteLLM, llama-swap, других моделей и агентных инструментов намеренно не включена.
