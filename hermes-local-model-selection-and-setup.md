# Выбор локальной модели для Hermes на RTX 3060 12 GB

Практическое руководство для Ubuntu: как сравнить и подключить локальные языковые модели к Hermes Agent через существующий стек `Hermes → LiteLLM → llama-swap → llama.cpp`.

> **Статус:** план установки и тестирования. Победитель заранее не выбран: модели нужно сравнить на одинаковых задачах.

## 1. Цель

Нужна не просто самая большая модель, которую можно запустить на компьютере, а модель, которая лучше всего работает именно как «мозг» Hermes:

- корректно выбирает инструменты и формирует аргументы;
- использует результат инструмента для следующего шага;
- выполняет многошаговые задачи и проверяет результат;
- пишет и исправляет код;
- соблюдает инструкции и не заявляет об успехе без проверки;
- обеспечивает приемлемую скорость.

**Hermes** — агентная система, **Mistral/Qwen/DeepSeek** — модели, а **llama.cpp, llama-swap и LiteLLM** — инфраструктура запуска и маршрутизации. Qwen не заменяет Hermes: его можно подключить как модель для Hermes, как и Mistral или DeepSeek.

## 2. Исходная конфигурация

Зафиксированная конфигурация компьютера:

- GPU: NVIDIA GeForce RTX 3060, 12 GB VRAM.
- Системная RAM: около 11 GiB.
- Swap: `/swap.img`, 4 GiB.
- Рабочий хост: `ubuntu26`.
- Сборка llama.cpp: `~/llama.cpp/build-cublas/bin`.
- Архитектура сервисов:
  - Hermes → LiteLLM `127.0.0.1:4000`;
  - LiteLLM → llama-swap `127.0.0.1:8080`;
  - llama-swap → llama.cpp server на выделенном порту.
- Конфигурация llama-swap: `~/local-llm-stack/llama-swap.yaml`.
- Скрипт запуска моделей: `~/local-llm-stack/llama-model-launcher.sh`.

Ранее в API LiteLLM были видны alias: `qwen3.5-4b`, `ministral-3b`, `ministral-8b`, `deepseek-r1-7b`. Перед тестированием необходимо проверить точные версии весов: alias сам по себе не доказывает, какая именно модель установлена.

**Безопасность конфигурации:** не заменяйте рабочий `llama-swap.yaml` целиком и не публикуйте `.env`, API-ключи или токены. Сначала делайте резервную копию и проверяйте новые модели отдельно.

## 3. Кандидаты для испытаний

### Основной агент

1. **Qwen3.5-4B** — существующая базовая точка для измерения скорости, следования инструкциям и работы с инструментами.
2. **Текущий Ministral 3B** — кандидат на быстрые простые действия; сначала подтвердить точную версию весов.
3. **Ministral 3 8B** — основной кандидат для сравнения с компактным Qwen.
4. **Текущий Ministral 8B** — проверить, не относится ли он к более старому поколению. `ministral-8b` и `Ministral 3 8B` не обязательно одна и та же модель.

### Код и сложные задачи

5. **Qwen3.6-35B-A3B IQ2_XXS** — крупный MoE-эксперимент, уже запускавшийся отдельно на порту `8999`. Нужно проверить качество, скорость, потребление памяти и вызовы инструментов.
6. **Devstral Small 2** — специализированный кандидат для агентного программирования. Перед установкой проверьте доступность совместимой GGUF-квантизации, размер файла, контекст и поддержку текущей сборкой llama.cpp.
7. **DeepSeek-R1-Distill-Qwen-7B** — кандидат для рассуждений и анализа ошибок. Хорошие рассуждения не гарантируют надёжных вызовов инструментов.

Это список для испытаний, а не рейтинг. Не выбирайте модель только по числу параметров или общим бенчмаркам.

## 4. Проверка текущей системы

Выполните на Ubuntu:

```bash
free -h
nvidia-smi
```

Посмотрите параметры, которые поддерживает установленная сборка llama.cpp:

```bash
~/llama.cpp/build-cublas/bin/llama-server --help 2>&1 \
  | grep -E -A 2 -- '--cpu-moe|--n-cpu-moe|--gpu-layers|--fit|--ctx-size'
```

Проверьте конфигурацию маршрутизатора:

```bash
grep -nE 'name:|model:|model_path|alias:|path:|context|ctx' \
  ~/local-llm-stack/llama-swap.yaml
```

Перед редактированием сохраните резервную копию:

```bash
cp ~/local-llm-stack/llama-swap.yaml \
   ~/local-llm-stack/llama-swap.yaml.bak.$(date +%Y%m%d-%H%M%S)
```

Не отправляйте вывод, содержащий секреты, в публичные issue или репозитории.

## 5. Проверка LiteLLM API

В текущем стеке LiteLLM слушает `127.0.0.1:4000`. Сначала убедитесь, что endpoint отвечает. Используйте свой ключ из локальной конфигурации, не вставляя его в документацию или чат:

```bash
curl -sS http://127.0.0.1:4000/v1/models \
  -H "Authorization: Bearer $LITELLM_MASTER_KEY"
```

Проверьте модель по точному alias, возвращённому `/v1/models`:

```bash
curl -sS http://127.0.0.1:4000/v1/chat/completions \
  -H "Authorization: Bearer $LITELLM_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "ministral-8b",
    "messages": [
      {"role": "user", "content": "Ответь ровно: MODEL_OK"}
    ],
    "temperature": 0
  }'
```

Замените `ministral-8b`, если в вашем API используется другой alias. Успешный простой ответ подтверждает доступность API, но не доказывает корректную работу tool calling.

## 6. Подключение к Hermes

Hermes должен обращаться к LiteLLM, если именно LiteLLM является настроенным шлюзом для локальных моделей.

1. Выйдите из активного чата Hermes в терминал, если команда настройки недоступна внутри сессии.
2. Запустите:

   ```bash
   hermes model
   ```

3. Выберите `Custom endpoint` (название пункта зависит от версии Hermes).
4. Укажите:
   - **Base URL:** `http://127.0.0.1:4000/v1`
   - **API key:** значение действующего `LITELLM_MASTER_KEY`
   - **Model name:** точный alias из `/v1/models`
   - **Context length:** реальное значение, которое поддерживают модель и сервер.
5. Откройте новую сессию Hermes и проверьте обычный ответ.
6. Затем попросите Hermes выполнить безопасное действие через инструмент, например вывести текущую рабочую директорию (`pwd`). Убедитесь, что он действительно вызвал инструмент, получил результат и продолжил работу.

Если интерфейс установленной версии Hermes отличается, ориентируйтесь на подсказки этой версии и её официальную документацию.

### Контекст и память

Не задавайте большой контекст только в клиенте, если сервер не настроен на него. Длина контекста влияет на память, а возможности зависят от конкретной модели, квантизации, настроек сервера и версии Hermes. Проверьте актуальные требования Hermes к контексту перед постоянным использованием модели. Если контекст сервера меньше нужного, это не исправляется одним лишь изменением поля в Hermes.

### Если чат работает, а инструменты — нет

Проверьте:

- поддержку function/tool calling конкретной моделью;
- chat template и параметры `--jinja` в llama.cpp;
- совместимость формата tool calls между моделью, LiteLLM и Hermes;
- логи сервисов и реальный ответ инструмента.

Не считайте интеграцию завершённой только потому, что модель отвечает на обычные сообщения.

## 7. Отдельный эксперимент Qwen3.6-35B-A3B

Сохранённый эксперимент использует файл:

`/home/oleg/models/Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf`

Пример `run.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

MODEL="/home/oleg/models/Qwen3.6-35B-A3B-UD-IQ2_XXS.gguf"
LLAMA_SERVER="/home/oleg/llama.cpp/build-cublas/bin/llama-server"

exec "$LLAMA_SERVER" \
  -m "$MODEL" \
  -c 4096 \
  -ngl 999 \
  --flash-attn on \
  --jinja \
  --host 127.0.0.1 \
  --port 8999 \
  --alias qwen3.6-35b-experiment
```

Если скрипт уже сохранён в экспериментальном каталоге:

```bash
cd ~/local-llm-stack/experiments/qwen3.6-35b
./run.sh
```

API endpoint: `http://127.0.0.1:8999/v1`.

Проверка:

```bash
curl -sS http://127.0.0.1:8999/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.6-35b-experiment",
    "messages": [
      {"role": "user", "content": "Ответь ровно: QWEN35_OK"}
    ],
    "temperature": 0
  }'
```

`-ngl 999` просит llama.cpp выгрузить на GPU все возможные слои; это не гарантирует, что модель с любым контекстом поместится в VRAM. В этом эксперименте указан контекст **4096**, поэтому его нельзя автоматически считать готовой основной моделью Hermes, если установленная версия Hermes требует более длинного контекста. Сначала измерьте память и скорость и проверьте реальную совместимость.

Этот эксперимент использует **llama.cpp**, а не AirLLM. AirLLM — отдельный метод послойного инференса, упоминавшийся только как справочный вариант.

## 8. Единый протокол сравнения моделей

Каждой модели нужно дать один и тот же набор задач и записывать не только текст ответа, но и реальные действия инструмента.

### Тест A — вызов инструмента

Попросить прочитать заранее созданный тестовый файл через инструмент терминала. Проверить, что модель действительно вызвала инструмент, передала корректные аргументы и использовала вывод.

### Тест B — многошаговая задача

Попросить создать небольшой файл, запустить тест, прочитать ошибку и исправить её. Засчитывать решение только после проверки результата.

### Тест C — программирование

Дать небольшой воспроизводимый баг с тестом. Исправление считается успешным, только если тест проходит и соседний сценарий не сломан.

### Тест D — устойчивость

Проверить, что модель не выдумывает результат инструмента, сообщает об ошибках и не объявляет задачу выполненной без проверки.

### Тест E — скорость и память

Записывать:

- время до первого токена;
- полное время выполнения задачи;
- скорость генерации, если доступна;
- пиковую VRAM;
- RAM и swap;
- число вызовов инструментов и неудачных попыток.

| Модель | Tool calling (0–5) | Код (0–5) | Рассуждение (0–5) | Инструкции (0–5) | Время | VRAM/RAM | Примечания |
|---|---:|---:|---:|---:|---:|---|---|
| Qwen3.5-4B | | | | | | | |
| Текущий Ministral 3B | | | | | | | |
| Текущий Ministral 8B | | | | | | | |
| Ministral 3 8B | | | | | | | |
| Qwen3.6-35B-A3B IQ2_XXS | | | | | | | |
| Devstral Small 2 | | | | | | | |

Заполняйте оценки только после тестов, а не на основе предположений.

## 9. Рекомендуемый порядок действий

1. Зафиксировать точные версии установленных Qwen и Ministral.
2. Прогнать одинаковые тесты на уже доступных моделях.
3. Отдельно установить и испытать Ministral 3 8B, если его ещё нет.
4. Затем проверить специализированную модель для программирования.
5. Испытать Qwen3.6-35B-A3B на сложных задачах с учётом контекста и памяти.
6. Не менять одновременно несколько компонентов стека: иначе будет трудно определить причину улучшения или регрессии.
7. Выбрать надёжную основную модель, а более крупную использовать для сложных задач, если качество оправдывает задержку.

**Предварительная гипотеза для первого теста:** сравнить текущий Qwen3.5-4B с актуальным Ministral 3 8B. Это не утверждение, что один из них лучше; это практичный эксперимент на существующем оборудовании.
