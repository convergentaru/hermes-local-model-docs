### Зафиксированные тесты

1. `jcode --provider-profile unsloth-qwen auth-test`
   - `credential_probe`: ключ найден по локальному credential source;
   - `refresh_probe`: skipped;
   - `provider_smoke`: FAILED — model discovery получил HTTP 401 с текстом `Missing bearer authentication in header`.
   - Это означает, что конкретный запрос model discovery получил ответ без принятого Bearer-заголовка. Не делать вывод, что сама модель сломана.

2. `jcode --provider-profile unsloth-qwen run 'Reply exactly: JCODE_UNSLOTH_OK'`
   - Команда дошла до HTTP endpoint `http://127.0.0.1:52681/v1/chat/completions`.
   - Результат: TCP `Connection refused` (os error 111).
   - HTTP-ответа от сервера не было; поэтому этот тест не проверяет корректность API key или Bearer header.

Вывод: сейчас есть две отдельные проблемы/наблюдения — предыдущий HTTP 401 при model discovery и более поздний TCP refusal при прямом run. Не смешивать их. Сначала вернуть доступный Unsloth listener; затем проверять runtime. `auth-test` не считать достаточным доказательством работоспособности/неработоспособности генерации.

### Особенность запуска

- `jcode run` — отдельный headless one-shot путь; он сразу инициализирует provider и делает HTTP-запрос.
- Запуск `jcode` без подкоманды — интерактивный клиент с локальным daemon/socket lifecycle.
- Если TUI зависает при запуске, диагностировать отдельно socket/daemon/handshake и startup logs. Не считать это автоматически проблемой модели или API.
- Не запускать несколько демонов и не удалять socket вслепую.
