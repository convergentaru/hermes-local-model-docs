# Локальная AI-лаборатория: Hermes, LEGO/CAD, компьютерное зрение и анализ крыш

**Статус:** план проекта и техническая дорожная карта. Кандидаты на модели отмечены как кандидаты, пока они не прошли тесты на целевом компьютере.

## 1. Цель проекта

Построить локальную рабочую среду на Ubuntu для четырёх направлений:

1. **Агентная разработка:** программирование, исправление кода, написание скриптов для серверов, WordPress-плагинов, React и Android-проектов.
2. **LEGO и CAD:** анализ изображений, создание LEGO-конструкций, генерация LDraw и CAD-скриптов для OpenSCAD/FreeCAD.
3. **Компьютерное зрение:** анализ фотографий и аэрофотоснимков, выделение объектов и извлечение измеримых признаков.
4. **Анализ крыш:** поиск зданий в Нидерландах, выделение крыш, оценка площади и видимых признаков покрытия на основании разрешённых источников данных.

Рабочее ограничение — компьютер с Ubuntu, NVIDIA RTX 3060 12 GB VRAM, около 11 GiB системной RAM и 4 GiB swap. Главный принцип: **local-first**. Платные API не являются обязательной частью архитектуры. Бесплатные внешние сервисы можно рассматривать отдельно, но основные рабочие сценарии должны оставаться локальными.

## 2. Базовая архитектура

Для экспериментальной конфигурации:

```text
Hermes Desktop
   ├── инструменты агента: терминал, файлы, браузер
   ├── память и навыки
   ├── голосовой ввод (отдельный STT-компонент)
   └── задачи LEGO/CAD и геоаналитики
           |
           v
      llama.cpp server
           |
           v
  одна выбранная локальная GGUF-модель
           |
           v
     RTX 3060 + CPU/RAM
```

Используется уже собранный `llama.cpp` с CUDA. Модель запускается непосредственно через сервер `llama.cpp`, например на локальном адресе `http://127.0.0.1:8999/v1`. Для этого экспериментального пути LiteLLM и llama-swap не обязательны. Существующие сервисы и конфигурации не удаляются: экспериментальная цепочка должна быть изолирована и использовать отдельный порт.

Не следует запускать все большие модели одновременно. Веса хранятся на диске, но на время теста загружается одна модель. Если память позволяет и испытания подтверждают пользу, позже можно добавить вторую модель для служебных задач.

## 3. Эталон: уже проверенная Qwen3.6-35B-A3B

Для Qwen3.6-35B-A3B в квантовании IQ2_XXS сохранились журналы `llama.cpp` от 2 октября 2026 года.

Зафиксированные результаты при контексте 10 240 токенов:

- генерация длинного ответа: около 13,3 токена/с;
- несколько коротких ответов: приблизительно 14–15 токенов/с;
- обработка входного промпта в одном из тестов с примерно 9 951 токеном: около 292 токенов/с;
- генерация 3 615 токенов заняла около 272 секунд.

Это эталон прежней конфигурации, а не гарантированный прогноз для контекста 64K или для других моделей. Перед сравнением необходимо записывать контекст, квантование, параметры GPU/CPU offloading, скорость обработки промпта, скорость генерации, память и качество вызова инструментов.

Параметры, подобранные для Qwen, не следует без проверки копировать на другую архитектуру. Механизмы `llama.cpp` — CUDA, Flash Attention, настройка контекста, offloading и подбор параметров — применимы к поддерживаемым моделям, но реальные параметры зависят от структуры весов и версии движка.

## 4. Подбор языковых моделей

Модели ниже — **кандидаты для испытания**, а не рейтинг с заранее гарантированной скоростью.

| Модель | Предполагаемая роль | Что проверить |
|---|---|---|
| Qwen3.5-9B Q4_K_M | Основной повседневный агент: код, файлы, инструменты | Вызов инструментов, контекст 64K, скорость и RAM/VRAM |
| GLM-4.7-Flash IQ2_XXS | Альтернатива большой MoE-модели для сложных задач | Поддержку GGUF текущей сборкой, шаблон чата, стабильность и память |
| Gemma 4 E4B | Компактная мультимодальная модель для экспериментов с изображениями | Совместимость модели и мультимодального проектора, качество на LEGO/снимках |
| Ministral 3 8B Instruct | Альтернатива Qwen для агентных и кодовых задач | Точную GGUF-сборку, function calling и скорость |
| DeepSeek-R1-Distill-Qwen-14B | Сравнение многошаговых рассуждений | Память, скорость и надёжность инструментов |
| GPT-OSS-20B | Отдельный эксперимент с открытой моделью OpenAI | Фактическую возможность комфортного запуска на имеющейся памяти |
| Saiga-YandexGPT-8B | Сравнение качества русского языка | GGUF, шаблон чата и выполнение инструментальных задач |
| QVikhr-3-4B-Instruction | Компактная русскоязычная модель | Качество инструкций и вызовов инструментов |
| Уже установленная Ministral-3B | Базовый тест быстрой небольшой модели | Сравнить со всеми кандидатами на одинаковых коротких задачах |

Не все модели будут одинаково хорошо работать с каждым агентом. Поддержка API сама по себе не гарантирует, что модель корректно создаёт структурированные вызовы функций. Для каждой модели нужно отдельно проверить шаблон чата, режим рассуждений и цикл tool call → результат инструмента → следующий шаг.

Новые и крупные GGUF загружать только после проверки точного репозитория, имени файла, квантования и размера. Не следует использовать массовый загрузчик с непроверенными именами файлов.

## 5. LEGO: специализированная генерация и CAD

### Форматы и компоненты

- **LDraw** — базовый формат для представления LEGO-моделей и передачи конструкций между совместимыми программами.
- **BrickGPT/LegoGPT** — исследовательское направление для генерации физических LEGO-конструкций по текстовым описаниям и работе со сборками.
- **LDraw Nova** — агентный проект, который стоит изучить как пример конвейера генерации более крупных LDraw-конструкций. Его готовность к работе только с локальными бесплатными моделями нужно проверить.
- **OpenSCAD** — CAD через программный код, подходящий для генерации параметрической геометрии.
- **FreeCAD** — CAD-система с Python API/макросами для создания и изменения моделей.

Источники для первичного изучения:

- BrickGPT: https://github.com/strategist922/brickgpt
- LDraw Nova: https://github.com/anteloc/ldraw-nova
- LDraw: https://www.ldraw.org/
- OpenSCAD: https://openscad.org/
- FreeCAD: https://www.freecad.org/
- llama.cpp: https://github.com/ggml-org/llama.cpp

Первый MVP: текстовое описание → создание/генерация LDraw → автоматическая проверка структуры и доступности деталей → открытие результата в совместимом просмотрщике. Второй этап: изображение → визуальное описание → гипотеза о деталях и геометрии → LDraw/CAD → проверка. Не следует предполагать, что любая VLM с одного снимка способна восстановить точную 3D-конструкцию.

Для CAD-скриптов Hermes может писать OpenSCAD-код и Python-макросы FreeCAD, запускать проверки и сохранять исходники. Валидация должна включать хотя бы успешный запуск CAD-инструмента и проверку полученного файла.

## 6. Изображения и компьютерное зрение

Для анализа фотографий требуется мультимодальная модель (VLM), способная принимать изображения, а не только текст. Gemma 4 E4B — один из кандидатов для первого локального испытания. Также можно тестировать поддерживаемые `llama.cpp` варианты Qwen-VL, проверяя совместимость конкретного GGUF и компонентов для обработки изображений.

Разделять две задачи:

1. **VLM** описывает картинку и помогает агенту определить следующий шаг.
2. **Специализированное компьютерное зрение** выполняет детекцию/сегментацию и измерения с повторяемым результатом.

Площадь, контуры и расстояния следует получать из изображений или геоданных с помощью CV/GIS-алгоритмов, а не полагаться только на словесную оценку VLM.

Документация мультимодального интерфейса llama.cpp: https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md

## 7. Анализ крыш в Нидерландах

Для первого прототипа предпочтительны открытые и лицензированные наборы данных, а не массовое извлечение тайлов из потребительских картографических приложений.

### Источники

- **PDOK Luchtfoto** — государственные аэрофотоснимки Нидерландов с различными периодами съёмки и разрешениями. У каждого набора нужно проверять год, разрешение, условия лицензии и атрибуцию: https://www.pdok.nl/
- **BAG** — государственный реестр зданий и адресов, который можно использовать для контуров/идентификации зданий через сервисы PDOK: https://www.pdok.nl/ogc-apis
- **AHN** — высотные данные Нидерландов, пригодные для анализа рельефа и, где данные позволяют, геометрии крыш: https://www.ahn.nl/open-data

Условия использования проверять для конкретного слоя перед массовой загрузкой и коммерческим использованием. Не предполагать, что любое изображение из Google Maps или Яндекс.Карт можно свободно массово извлекать, хранить или использовать для обучения.

### Конвейер обработки

1. Получить разрешённые аэрофотоснимки выбранного района.
2. Получить геометрию зданий из BAG и совместить координатные системы.
3. Вырезать фрагменты снимков для каждого здания.
4. Выделить контур крыши с помощью CV-сегментации.
5. Измерить площадь проекции, цветовые признаки и видимые классы объектов (например, солнечные панели), сохраняя оценку уверенности.
6. При наличии совместимых высотных данных оценить геометрию и потенциальную площадь наклонной поверхности; не путать её с площадью горизонтальной проекции.
7. Хранить результат вместе с источником данных, датой снимка, версией модели и показателями уверенности.
8. Отмечать низкоуверенные случаи для ручной проверки.

**Ограничение:** один снимок не позволяет надёжно диагностировать герметичность, протечки или состояние скрытых слоёв кровли. На первом этапе цель — визуальная инвентаризация и ранжирование объектов по видимым признакам, а не окончательное заключение о техническом состоянии крыши.

## 8. Обучение и донастройка с Unsloth

Unsloth имеет смысл подключить после получения базового рабочего результата и сбора примеров. Начать с небольшой модели примерно 3B–8B и LoRA/QLoRA, а не пытаться обучать 35B-модель в условиях 12 GB VRAM.

Возможные данные для дообучения:

- задача по WordPress → исправный код и тесты;
- описание параметрической детали → OpenSCAD-код;
- техническое задание для FreeCAD → Python-макрос;
- текстовое описание LEGO-сборки → корректный LDraw-результат;
- цель агента → ожидаемые последовательности вызовов инструментов;
- визуальные наблюдения → валидированный JSON с атрибутами.

Для CV-сегментации крыш потребуется отдельный обучающий конвейер на изображениях и размеченных масках; это не заменяется дообучением обычной текстовой модели в Unsloth.

Unsloth: https://unsloth.ai/docs

## 9. Голос, Hermes и работа без платных API

Hermes Desktop остаётся основным интерфейсом пользователя и оркестратором. Распознавание речи — отдельный компонент; первым вариантом следует проверить локальный STT, например Whisper/Faster-Whisper. TTS нужен только если требуется озвучивать ответы.

Рабочий контур должен оставаться локальным:
- Hermes Desktop → локальный `llama.cpp`;
- локальные инструменты для файлов, CAD и геоаналитики;
- локальный голосовой ввод;
- платные API не являются условием работы.

Claude Code рассматривать как отдельный эксперимент. Официальная поддержка Claude Code ориентирована на сервисы Anthropic и совместимые авторизованные настройки; полностью бесплатная работа с произвольной локальной моделью не гарантируется. Если потребуется платный доступ, Claude Code не включать в основной обязательный контур. Не настраивать обход авторизации или платёжных ограничений.

## 10. План внедрения

### Этап A — надёжная локальная база
- Зафиксировать существующие версии `llama.cpp`, Hermes и рабочие настройки.
- Запустить одну модель напрямую через `llama.cpp`.
- Проверить контекст 64K, время до первого токена, скорость генерации, RAM/VRAM и OOM.
- Проверить реальные вызовы терминала и чтение/создание тестового файла.
- Сохранить результаты в таблицу, не смешивать измерения разных контекстов.

### Этап B — повседневная разработка
- Сравнить Ministral-3B, Qwen3.5-9B и GLM-4.7-Flash.
- Выполнить одинаковые тесты WordPress, React/Android и серверного скрипта.
- Выбрать основную дневную модель по качеству, скорости и стабильности.
- Оставить Qwen3.6-35B-A3B как тяжёлую модель для ночных задач, если её качество оправдывает время выполнения.

### Этап C — LEGO/CAD
- Изучить и проверить BrickGPT/LegoGPT.
- Создать первый воспроизводимый сценарий генерации LDraw.
- Подключить OpenSCAD/FreeCAD и автоматические проверки файлов.
- Добавить визуальный вход только после работающего текстового конвейера.

### Этап D — крыши
- Выбрать небольшой район и один разрешённый набор PDOK.
- Связать снимки с контурами BAG.
- Построить прототип сегментации и измерения площадей.
- Сохранить качество, источники, даты и уверенность результатов.

### Этап E — обучение
- Собирать только валидированные пары «задача → правильный результат».
- Сначала проверить качество базовой модели и prompt/tooling.
- Затем проводить небольшой LoRA/QLoRA эксперимент через Unsloth.
- Для сегментации крыш создать отдельный набор изображений и масок.

## 11. Критерии успеха

Проект развивается успешно, если:
- модель стабильно работает в имеющейся памяти и с требуемым контекстом;
- Hermes реально вызывает инструменты, а не только сообщает о выполнении;
- CAD-файлы создаются и открываются в целевом приложении;
- LEGO-результаты проверяются в формате LDraw;
- анализ крыш воспроизводим, привязан к источнику снимка и сохраняет уверенность/ограничения;
- обучающие наборы содержат проверенные результаты;
- платный API не является необходимым для базового рабочего контура.

**Основной принцип:** сначала получить работающий специализированный конвейер, затем улучшать его моделью или дообучением. Не пытаться решать задачи LEGO, CAD, GIS и агентного программирования одной неподготовленной LLM.
