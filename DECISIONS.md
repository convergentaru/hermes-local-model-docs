# DECISIONS — журнал архитектурных решений

## D-001 — единый репозиторий памяти локальной AI-инфраструктуры

Дата: 2026-10-31  
Статус: ACCEPTED

Решение: использовать `convergentaru/hermes-local-model-docs` как главный центр документации и памяти для Unsloth, Hermes, Claude Code, GGUF-моделей, llama.cpp и диагностики.

Причины:
- в репозитории уже есть история экспериментов и инструкции;
- не нужно создавать дублирующий репозиторий;
- можно разделить проверенные настройки, текущее состояние, ошибки и следующие действия.

## D-002 — не запускать две копии одной модели одновременно

Дата: 2026-10-31  
Статус: ACCEPTED

Решение: в текущем этапе использовать одну загруженную Qwen3.5-9B через Unsloth. Не запускать вторую копию той же GGUF через Hermes llama-server.

Причина: в предыдущем снимке две копии занимали примерно 11.8 GiB из 12 GiB VRAM.

## D-003 — GUI Unsloth является предпочтительным способом выбора и настройки модели

Дата: 2026-10-31  
Статус: ACCEPTED

Решение: восстановить прежний рабочий профиль через Unsloth Desktop/Studio GUI. Не заменять его догадками о CLI-командах.

Причина: пользователь подтверждает, что ранее модель выбиралась и настраивалась в desktop-приложении; предложенная 2026-10-31 CLI-команда завершилась ошибкой.

## D-004 — статус VERIFIED требует функционального теста

Дата: 2026-10-31  
Статус: ACCEPTED

Решение: считать компонент рабочим только после реального теста запроса/ответа через нужный маршрут. Запуск процесса или открытый порт недостаточны.


## D-005 — one Unsloth-managed model, existing Hermes and Claude Code as separate clients

Дата: 2026-10-31  
Статус: ACCEPTED

Решение:
- Unsloth CLI управляет жизненным циклом единственной загруженной Qwen3.5-9B-Q4_K_M.
- Hermes использует Custom OpenAI-compatible Chat Completions endpoint Unsloth.
- Claude Code подключается к тому же уже работающему Unsloth server через поддерживаемый Unsloth маршрут; не поднимать вторую копию модели.
- Сессии, инструменты, память и роли Hermes и Claude Code остаются независимыми.
- Не запускать legacy `llama-server.service` Hermes, пока действует эта схема.

Причина: сохранить существующий Hermes Gateway и память, не расходовать VRAM на вторую копию модели и обеспечить единый inference backend.

## D-006 — Unsloth CLI является управляющим слоем запуска модели

Дата: 2026-10-31  
Статус: ACCEPTED

Решение: после перезагрузки запускать модель и её llama-server через установленный Unsloth CLI `unsloth`, а не самостоятельным прямым запуском `llama-server`.

Причина: Unsloth является выбранным управляющим слоем загрузки модели и жизненного цикла сервера. Сначала фиксировать фактически проверенную команду и результат, затем оформлять её как runbook.
