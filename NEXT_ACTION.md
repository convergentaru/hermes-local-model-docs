## Последнее фактическое состояние

- Hermes `llama-server.service` на `:18434` был остановлен пользователем командой `systemctl --user stop llama-server.service`.
- Hermes Gateway — отдельный unit; он не имеет systemd-зависимости от `llama-server.service`, но без model API на `:18434` не сможет отвечать через свою основную модель.
- Unsloth worker ранее слушал `:52681`, PID `212601`, но последующий jcode запрос получил `Connection refused`. Текущий порт не известен.
- jcode v0.99.1 и профиль `unsloth-qwen` установлены. Прямой запрос не дошёл до HTTP-обработчика, потому что TCP соединение было отклонено. Предыдущий auth-test отдельно завершался HTTP 401 Missing bearer.

## Следующий шаг после задач T-001 и T-002

Вернуться к незавершённому эксперименту jcode → существующая Qwen3.5-9B в Unsloth, не загружая вторую копию модели:

1. Открыть Unsloth Desktop/Studio.
2. Выбрать существующую Qwen3.5-9B GGUF по пути `/home/oleg/.hermes/models/Qwen3.5-9B-Q4_K_M.gguf` и загрузить через сохранённый профиль GUI. Не менять параметры до фиксации.
3. Установить фактический адрес/порт worker из Unsloth и проверить, что он реально слушает.
4. Только после этого сверить base URL профиля jcode `unsloth-qwen` с актуальным endpoint.
5. Выполнить прямой короткий smoke test jcode. Если вернулся HTTP 401 — отдельно разбирать Bearer header по коду v0.99.1; если Connection refused — сначала чинить жизненный цикл Unsloth worker.
6. После успешного прямого запроса проверить интерактивный jcode TUI и его daemon/socket отдельно.
